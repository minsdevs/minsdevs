## About

대학생으로 개발을 배우며, **아이디어 → 배포 → 피드백** 루프를 빠르게 도는 걸 좋아합니다.  
멋쟁이사자처럼·Apps in Toss·팀 프로젝트에서 프론트부터 백엔드·인프라까지 손을 댑니다.

**지향하는 바**
- 기능 나열이 아니라 **사용자 문제를 푸는 제품**을 만든다
- 설명 가능한 코드, 읽히는 README, 배포까지 책임진다
- AI는 “데모용”이 아니라 **제품 안의 도구**로 붙인다
- 혼자 끝내지 않고 **협업·문서·인수인계**까지 남긴다

**지금 관심**
- Product engineering (웹 / 모바일 / 미니앱)
- Full-stack TypeScript · 백엔드 설계 · ML을 서비스에 붙이기
- 인턴십 · 사이드 프로젝트 · 팀 빌딩 기회

## What I look for in interviews

짧게 말할 수 있는 포인트입니다.

1. **왜 만들었는지** — 누구의 어떤 불편을 줄였는지
2. **내가 맡은 범위** — 프론트 / API / DB / 배포 / ML 중 어디까지
3. **트레이드오프** — 왜 그 스택·그 구조를 골랐는지
4. **막힌 지점** — 버그·성능·협업에서 어떻게 풀었는지
5. **다음 개선** — 지금 다시 만든다면 무엇을 바꿀지

> 자세한 구현과 트레이드오프는 각 repo의 README에서 확인할 수 있습니다.
